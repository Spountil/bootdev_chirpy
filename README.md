# Chirpy - HTTP Server & REST API

> A social networking backend and RESTful API built in Go from the [Boot.dev](https://www.boot.dev) course: **Learn HTTP Servers**.

Chirpy is a Twitter/X-like microblogging service and web server that showcases core backend engineering concepts in Go: HTTP routing (`net/http`), static asset serving, atomic hit metrics, PostgreSQL relational database modeling, database migrations with Goose, type-safe SQL query generation with `sqlc`, password hashing with Argon2id, JWT access tokens, refresh token rotation, and webhook integration.

## Features

- **Static File Serving & Request Metrics**:
  - Serves static assets on `/app/` with an atomic counter middleware tracking visits.
  - HTML admin dashboard displaying total file server hits.
  - Dev-only database reset endpoint (`POST /admin/reset`).
- **User Authentication & Management**:
  - Secure password hashing using **Argon2id**.
  - JWT (JSON Web Tokens) access token authentication (1-hour expiration, HS256).
  - Refresh tokens stored in PostgreSQL with 60-day validity and revocation support.
  - User profile updates (email and password).
- **Chirp (Post) Management**:
  - Create chirps up to 140 characters.
  - Automated profanity filter replacing flagged words (`kerfuffle`, `sharbert`, `fornax`) with `****` (case-insensitive).
  - Fetch chirps by ID or list all chirps.
  - Filter chirps by author (`?author_id=<uuid>`).
  - Sort chirps in ascending or descending chronological order (`?sort=desc`).
  - Delete chirps with strict author verification (403 Forbidden if not the creator).
- **Webhooks & Membership Upgrades**:
  - Polka payment (fake service) webhook integration (`POST /api/polka/webhooks`).
  - Secured via API Key header (`Authorization: ApiKey <KEY>`).
  - Upgrades users to **Chirpy Red** membership upon receiving `user.upgraded` events.

## Database Schema & Migrations

The database consists of three relational tables managed with **Goose**:

### 1. `users`
| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | UUID | PRIMARY KEY | Unique user identifier |
| `created_at` | TIMESTAMP | NOT NULL | Creation timestamp |
| `updated_at` | TIMESTAMP | NOT NULL | Last update timestamp |
| `email` | TEXT | NOT NULL, UNIQUE | User's unique email address |
| `hashed_password` | TEXT | DEFAULT 'unset' | Argon2id password hash |
| `is_chirpy_red` | BOOLEAN | DEFAULT FALSE | Chirpy Red tier status |

### 2. `chirps`
| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | UUID | PRIMARY KEY | Unique chirp identifier |
| `created_at` | TIMESTAMP | NOT NULL | Creation timestamp |
| `updated_at` | TIMESTAMP | NOT NULL | Last update timestamp |
| `body` | TEXT | NOT NULL | Chirp message content (max 140 chars) |
| `user_id` | UUID | NOT NULL, FK -> `users(id)` ON DELETE CASCADE | Author user ID |

### 3. `refresh_tokens`
| Column | Type | Constraints | Description |
|---|---|---|---|
| `token` | TEXT | PRIMARY KEY | 256-bit hex-encoded token string |
| `created_at` | TIMESTAMP | NOT NULL | Creation timestamp |
| `updated_at` | TIMESTAMP | NOT NULL | Last update timestamp |
| `user_id` | UUID | NOT NULL, FK -> `users(id)` ON DELETE CASCADE | Associated user ID |
| `expires_at` | TIMESTAMP | NOT NULL | Expiration date (created_at + 60 days) |
| `revoked_at` | TIMESTAMP | DEFAULT NULL | Revocation timestamp if revoked |

## Environment Variables

Create a `.env` file in the root directory:

```env
DB_URL="postgres://postgres:postgres@localhost:5432/chirpy?sslmode=disable"
PLATFORM="dev"
TOKEN="your-super-secret-jwt-signing-key"
POLKA_KEY="your-polka-webhook-api-key"
```

| Variable | Required | Description |
|---|---|---|
| `DB_URL` | Yes | PostgreSQL connection string |
| `PLATFORM` | Yes | Set to `dev` to allow calling `POST /admin/reset` |
| `TOKEN` | Yes | Secret string used for signing and validating JWTs |
| `POLKA_KEY` | Yes | Secret API key for Polka payment webhooks |

## Getting Started

### Prerequisites

- **Go**: 1.22 or higher installed ([Download Go](https://go.dev/dl/))
- **PostgreSQL**: Running instance ([Download PostgreSQL](https://www.postgresql.org/download/))
- **Goose CLI**: For database migrations
  ```bash
  go install github.com/pressly/goose/v3/cmd/goose@latest
  ```
- **sqlc CLI** (Optional, for regenerating DB queries):
  ```bash
  go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest
  ```

### Installation & Setup

1. **Clone the repository and enter the project folder**:
   ```bash
   cd bootdotdev/bootdev_chirpy
   ```

2. **Install Go dependencies**:
   ```bash
   go mod download
   ```

3. **Create the database in PostgreSQL**:
   ```sql
   CREATE DATABASE chirpy;
   ```

4. **Set up `.env`**:
   Configure `DB_URL`, `PLATFORM`, `TOKEN`, and `POLKA_KEY` in `.env`.

### Running Migrations

Run Goose migrations against your PostgreSQL database:

```bash
cd sql/schema
goose postgres "postgres://postgres:postgres@localhost:5432/chirpy?sslmode=disable" up
cd ../..
```

To rollback a migration:
```bash
cd sql/schema
goose postgres "postgres://postgres:postgres@localhost:5432/chirpy?sslmode=disable" down
cd ../..
```

### Generating SQL with sqlc

Whenever you modify any query in `sql/queries/*.sql` or schema in `sql/schema/*.sql`, regenerate the Go database package:

```bash
sqlc generate
```

### Running the Application

Start the HTTP server on port `:8080`:

```bash
go run .
```

You can now visit `http://localhost:8080/app/` in your browser.

## API Documentation

### Overview & Error Format

- All API endpoints are prefixed with `/api` or `/admin`.
- Request and response payloads use `application/json` unless specified otherwise.
- In case of client or server errors, responses return a JSON object with an `error` key:

```json
{
  "error": "Error message description"
}
```

### Health & Admin

#### 1. Health Check
Checks if the server is up and responsive.

- **Method**: `GET`
- **URL**: `/api/healthz`
- **Auth**: None
- **Response**: `200 OK`
  - **Content-Type**: `text/plain; charset=utf-8`
  - **Body**: `OK`

```bash
curl -X GET http://localhost:8080/api/healthz
```

---

#### 2. Get Hit Metrics
Returns an HTML page detailing how many times the `/app/` static fileserver has been accessed.

- **Method**: `GET`
- **URL**: `/admin/metrics`
- **Auth**: None
- **Response**: `200 OK`
  - **Content-Type**: `text/html; charset=utf-8`
  - **Body**:
    ```html
    <html>
      <body>
        <h1>Welcome, Chirpy Admin</h1>
        <p>Chirpy has been visited 5 times!</p>
      </body>
    </html>
    ```

```bash
curl -X GET http://localhost:8080/admin/metrics
```

---

#### 3. Reset Server & Database
Resets the file server hits counter to `0` and removes all users from the database. Only permitted if `PLATFORM=dev`.

- **Method**: `POST`
- **URL**: `/admin/reset`
- **Auth**: None (Environment check: requires `PLATFORM="dev"`)
- **Responses**:
  - `200 OK`: Server metrics and users table reset.
  - `403 Forbidden`: Returned if `PLATFORM != "dev"`.

```bash
curl -X POST http://localhost:8080/admin/reset
```

### Authentication & Users

#### 1. Create User
Registers a new user account with an email and password.

- **Method**: `POST`
- **URL**: `/api/users`
- **Auth**: None
- **Request Body**:
  ```json
  {
    "email": "user@example.com",
    "password": "supersecretpassword"
  }
  ```
- **Responses**:
  - `201 Created`:
    ```json
    {
      "id": "18f918e7-ff1b-4f52-8700-111111111111",
      "created_at": "2026-11-17T18:00:00Z",
      "updated_at": "2026-11-17T18:00:00Z",
      "email": "user@example.com",
      "is_chirpy_red": false
    }
    ```
  - `500 Internal Server Error`: Failed to hash password or duplicate user.

```bash
curl -X POST http://localhost:8080/api/users \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "supersecretpassword"}'
```

---

#### 2. Login
Authenticates user credentials and returns both an access JWT and a 60-day refresh token.

- **Method**: `POST`
- **URL**: `/api/login`
- **Auth**: None
- **Request Body**:
  ```json
  {
    "email": "user@example.com",
    "password": "supersecretpassword"
  }
  ```
- **Responses**:
  - `200 OK`:
    ```json
    {
      "id": "18f918e7-ff1b-4f52-8700-111111111111",
      "created_at": "2026-11-17T18:00:00Z",
      "updated_at": "2026-11-17T18:00:00Z",
      "email": "user@example.com",
      "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "refresh_token": "a4f89d34e6b12a87c...",
      "is_chirpy_red": false
    }
    ```
  - `401 Unauthorized`: Password incorrect.
  - `500 Internal Server Error`: User not found or server error.

```bash
curl -X POST http://localhost:8080/api/login \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "supersecretpassword"}'
```

---

#### 3. Refresh Access Token
Exchanges an active, unexpired, non-revoked refresh token for a fresh 1-hour access JWT.

- **Method**: `POST`
- **URL**: `/api/refresh`
- **Headers**:
  - `Authorization: Bearer <REFRESH_TOKEN>`
- **Responses**:
  - `200 OK`:
    ```json
    {
      "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
    }
    ```
  - `401 Unauthorized`: Token not found, expired, or revoked.

```bash
curl -X POST http://localhost:8080/api/refresh \
  -H "Authorization: Bearer <REFRESH_TOKEN>"
```

---

#### 4. Revoke Refresh Token
Revokes a refresh token immediately so it cannot be used again to request new access tokens.

- **Method**: `POST`
- **URL**: `/api/revoke`
- **Headers**:
  - `Authorization: Bearer <REFRESH_TOKEN>`
- **Responses**:
  - `204 No Content`: Successfully revoked.
  - `500 Internal Server Error`: Extraction or revocation error.

```bash
curl -X POST http://localhost:8080/api/revoke \
  -H "Authorization: Bearer <REFRESH_TOKEN>"
```

---

#### 5. Update User Profile
Updates the authenticated user's email and password.

- **Method**: `PUT`
- **URL**: `/api/users`
- **Headers**:
  - `Authorization: Bearer <ACCESS_TOKEN>`
- **Request Body**:
  ```json
  {
    "email": "newemail@example.com",
    "password": "newpassword123"
  }
  ```
- **Responses**:
  - `200 OK`:
    ```json
    {
      "id": "18f918e7-ff1b-4f52-8700-111111111111",
      "created_at": "2026-11-17T18:00:00Z",
      "updated_at": "2026-11-17T18:30:00Z",
      "email": "newemail@example.com"
    }
    ```
  - `401 Unauthorized`: Invalid or missing access token.

```bash
curl -X PUT http://localhost:8080/api/users \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"email": "newemail@example.com", "password": "newpassword123"}'
```

### Chirps

#### 1. Create Chirp
Creates a new chirp message attributed to the authenticated user. Profane words (`kerfuffle`, `sharbert`, `fornax`) are automatically censored to `****`. Max length is 140 characters.

- **Method**: `POST`
- **URL**: `/api/chirps`
- **Headers**:
  - `Authorization: Bearer <ACCESS_TOKEN>`
- **Request Body**:
  ```json
  {
    "body": "Hello world, having a kerfuffle today!"
  }
  ```
- **Responses**:
  - `201 Created`:
    ```json
    {
      "id": "7616113b-2407-4eef-bdfa-b159f81d1e4e",
      "created_at": "2026-11-17T18:45:00Z",
      "udpated_at": "2026-11-17T18:45:00Z",
      "body": "Hello world, having a **** today!",
      "user_id": "18f918e7-ff1b-4f52-8700-111111111111"
    }
    ```
  - `400 Bad Request`: Body exceeds 140 characters (`Chirp is too long.`).
  - `401 Unauthorized`: Invalid or missing bearer token.

```bash
curl -X POST http://localhost:8080/api/chirps \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"body": "Hello world!"}'
```

---

#### 2. Get All Chirps
Retrieves all chirps. Supports filtering by author and sorting by creation timestamp.

- **Method**: `GET`
- **URL**: `/api/chirps`
- **Query Parameters**:
  | Parameter | Type | Required | Description |
  |---|---|---|---|
  | `author_id` | UUID | No | Filter chirps written by a specific user ID |
  | `sort` | string | No | Order of chirps. `desc` sorts newest first; defaults to `asc` (oldest first) |
- **Auth**: None
- **Responses**:
  - `200 OK`:
    ```json
    [
      {
        "id": "7616113b-2407-4eef-bdfa-b159f81d1e4e",
        "created_at": "2026-11-17T18:45:00Z",
        "udpated_at": "2026-11-17T18:45:00Z",
        "body": "Hello world!",
        "user_id": "18f918e7-ff1b-4f52-8700-111111111111"
      }
    ]
    ```

```bash
# Get all chirps
curl -X GET http://localhost:8080/api/chirps

# Filter by author and sort descending
curl -X GET "http://localhost:8080/api/chirps?author_id=18f918e7-ff1b-4f52-8700-111111111111&sort=desc"
```

---

#### 3. Get Chirp by ID
Fetches a single chirp by its UUID.

- **Method**: `GET`
- **URL**: `/api/chirps/{chirpID}`
- **Auth**: None
- **Responses**:
  - `200 OK`:
    ```json
    {
      "id": "7616113b-2407-4eef-bdfa-b159f81d1e4e",
      "created_at": "2026-11-17T18:45:00Z",
      "udpated_at": "2026-11-17T18:45:00Z",
      "body": "Hello world!",
      "user_id": "18f918e7-ff1b-4f52-8700-111111111111"
    }
    ```
  - `400 Bad Request`: Invalid UUID format.
  - `404 Not Found`: Chirp does not exist.

```bash
curl -X GET http://localhost:8080/api/chirps/7616113b-2407-4eef-bdfa-b159f81d1e4e
```

---

#### 4. Delete Chirp
Deletes a chirp by ID. Only the chirp's author can delete their own chirp.

- **Method**: `DELETE`
- **URL**: `/api/chirps/{chirpID}`
- **Headers**:
  - `Authorization: Bearer <ACCESS_TOKEN>`
- **Responses**:
  - `204 No Content`: Chirp successfully deleted.
  - `400 Bad Request`: Invalid UUID format or chirp not found.
  - `401 Unauthorized`: Invalid or missing access token.
  - `403 Forbidden`: User is not the author of the chirp.
  - `404 Not Found`: Chirp could not be found to delete.

```bash
curl -X DELETE http://localhost:8080/api/chirps/7616113b-2407-4eef-bdfa-b159f81d1e4e \
  -H "Authorization: Bearer <ACCESS_TOKEN>"
```

### Webhooks (Polka)

#### 1. Handle Membership Upgrades
Webhook endpoint used by Polka to notify Chirpy when a user has upgraded to **Chirpy Red**.

- **Method**: `POST`
- **URL**: `/api/polka/webhooks`
- **Headers**:
  - `Authorization: ApiKey <POLKA_KEY>`
- **Request Body**:
  ```json
  {
    "event": "user.upgraded",
    "data": {
      "user_id": "18f918e7-ff1b-4f52-8700-111111111111"
    }
  }
  ```
- **Responses**:
  - `204 No Content`: User upgraded successfully, or event was ignored (event != `user.upgraded`).
  - `401 Unauthorized`: Missing or invalid `ApiKey`.
  - `404 Not Found`: Specified user does not exist in the database.

```bash
curl -X POST http://localhost:8080/api/polka/webhooks \
  -H "Authorization: ApiKey your-polka-webhook-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "event": "user.upgraded",
    "data": {
      "user_id": "18f918e7-ff1b-4f52-8700-111111111111"
    }
  }'
```
